## Hardened cursor-agent skill for Windows + explicit local-only execution

**WHAT:** Added 49 lines to `skills/cursor-agent/SKILL.md`: local-execution default, Preflight section, Windows PowerShell example, web-request ban in the worker safety block, loop-failure handling, and a preflight row in Quick Reference.

**WHY:** User hit a failure on native Windows where the agent looped PowerShell web requests (`irm 'https://cursor.com/install?win32=true' | iex` / Invoke-WebRequest) trying to install cursor-agent repeatedly. Root cause: the Windows installer adds `%LOCALAPPDATA%\cursor-agent` to the *user* PATH, which an already-running agent session never sees — so cursor-agent stays "not found" after a successful install and the agent reinstalls forever.

**KEY RESEARCH FINDINGS (cursor-agent 2026.06.11 CLI + cursor.com docs):**
- `cursor-agent -p` headless runs are ALWAYS local; no cloud flag exists on headless runs.
- Cloud Agents trigger only via `&` prompt prefix (interactive), cursor.com/agents, Slack, API, or `cursor-agent worker` — skill now bans all of these.
- Windows native binary: `%LOCALAPPDATA%\cursor-agent\cursor-agent.exe` with `agent.exe` alias.
- `--sandbox enabled|disabled` flag exists but wasn't added (no evidence of Windows sandbox issues).

**HOW VERIFIED:** GREEN-phase subagent test — fresh agent given only the updated SKILL.md answered both scenarios correctly (no-reinstall + absolute path on Windows; `-p` = local + three cloud bans). Two ambiguities it flagged were fixed (PowerShell-native path form, `&` prompt-text vs call-operator).

**IMPACT:** Windows delegation to Cursor should no longer dead-loop on install; cloud handoff is explicitly out of scope.
