## Added refactoring-test-suites skill (uncommitted)

**WHAT:** New skill `skills/refactoring-test-suites/SKILL.md`, guard test `tests/refactoring-test-suites.test.mjs`, README row, and docs/site entry (32 skills). Branch `feat/refactoring-test-suites`, uncommitted.

**WHY:** The user's work repo (~/source/Terraform, ~8,200 NUnit tests, ~30 min) grew from ~500 to ~8,000 tests in two weeks of agent slices. Its CLAUDE.md rules require full suites before every commit and new test files per page, which both grows and slows the suite.

**HOW:** writing-skills RED/GREEN/REFACTOR.
- A small JS fixture was too easy: Opus and Haiku both did well without the skill.
- The real signal came from read-only planning on the Terraform repo. Without the skill, Haiku missed a new WebApplicationFactory per test (~620 tests), real SMTP connects to localhost:25, and `dotnet publish` inside StaticHostingTests. It also said "Never remove tests that CLAUDE.md requires".
- With the skill: measure first, speed fixes before deletions, rules mapped across layers, a planted bug per deleted test, a ledger, and a rule-change proposal for the user.

**IMPACT:** Terraform findings to reuse: no NUnit parallelism configured; the TERRAFORM_TEST_SQLITE process env var blocks parallel runs; an 85% coverage floor in CI; .memories show 504 tests took 2m26s on one day and 17m on another. Opus also flagged committed secrets in Terraform appsettings files (out of scope; told the user).
