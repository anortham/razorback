## Patched review workflow docs

### WHAT
Updated the standalone review and pre-merge review docs to fix cross-harness gaps and reduce prompt bloat.

- Switched standalone review guidance from `HEAD~1` to merge-base review so branch reviews cover the full feature branch.
- Fixed the `PLAN_OR_REQUIREMENTS` placeholder mismatch in the standalone reviewer template.
- Added a no-delegation fix path to `pre-merge-review` for Gemini CLI and any `executing-plans` run without subagents.
- Removed the duplicated raw Julie-output handoff from `pre-merge-review/fix-dispatch-prompt.md` and kept Julie re-orientation with the worker or inline fixer.
- Tightened reviewer prompts to be findings-first instead of spending tokens on required strengths and recommendations.
- Added explicit Julie-first language to the main docs and bootstrap guidance so the rule applies to leads, implementers, reviewers, and fix workers.

### WHY
The prior docs could miss most of a branch during standalone review, left Gemini with no documented fix path after external review, and spent extra prompt tokens on duplicated context and filler review sections.

### HOW
Verified the current workflow docs with targeted grep and diff review, patched the affected markdown files, then ran focused verification checks (`git diff --check`, negative rg checks for removed patterns, positive rg checks for new Julie-first wording).

### IMPACT
Standalone reviews now describe the correct review range, pre-merge review now has a documented no-subagent path, and the review prompts are leaner and more consistent with razorback's findings-first review style.
