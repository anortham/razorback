## Removed unnecessary autonomous stopping points

### WHAT
Updated Razorback workflow skills so approved or explicitly requested autonomous work keeps moving until a real blocker or the PR boundary. Added regression coverage in `tests/autonomous-process-gates.test.mjs` and fixed the existing docs test harness to read from the active checkout instead of the main repo path.

### WHY
Several live skills still had stale human wake-ups: written-spec review after design approval, plan approval polling, reviewer-choice prompts, visual companion consent, worktree directory questions, baseline-failure ask prompts, stale interactive finishing language, and generic ask-the-user fallbacks in TDD/debugging/review/Gemini flows.

### HOW
Anchored the policy on the blocker taxonomy: decide and log when a plan-consistent path exists, stop only for real blockers, preserve destructive confirmations and final PR/merge boundary. Ran a read-only audit with subagents, patched live skills, added tests for the stale phrases, and fixed reviewer findings for remaining TDD/debugging ask fallbacks.

### IMPACT
Autonomous sessions now have fewer false wake-ups before and during execution. Tests catch the main stale gates so they do not drift back in quietly.
