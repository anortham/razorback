## Plan path reduction: one approval, one report commit, one gate run

**WHAT:** Branch `plan-path-reduction` (stacked on `review-cleanup`) changes the plan path in five skills.
- `finishing-a-development-branch`: Step 7 (write the PR URL back, commit, push) is gone. The report is one commit; `{{pr_url}}` renders as `opened after this report: gh pr view <branch>`. A `Complete` run saves no checkpoint. The three checkpoint rules (same commit, no duplicates, without Goldfish) are stated once in Step 4; other steps name only the moment and `next`.
- `writing-plans`: a plan needs its own approval only when it makes a consequential choice the user has not made. The approval question also asks for the reviewer choice and for push and PR authority.
- `brainstorming`: no approval section by section. The written spec is the one design approval, and that question carries the reviewer choice and the push and PR question.
- `executing-plans`, `subagent-driven-development`: they no longer run Check B or the final branch gate before the finish skill. They pass the list of worktrees and branches. SDD deletes its workspace only after the finish skill reports `Complete`.

**WHY:** The user asked for less ceremony with the same validation. The plan path had a fixed cost: three approvals of the same design, a publication stop at the end of each run, three metadata commits and two pushes, and two runs of the same checks.

**HOW:** Guard tests first (red), then the skill text. Step 4a stays as the fallback for a run that started without push and PR authority, so the `approval` and `approval_pause_recovery` evaluation scenarios still hold.

**IMPACT:** An approved run can end at a PR with no further stop. Full suite: 547 tests, 546 pass, 1 skipped. No fresh-agent pressure runs were done on the new text.
