## Release 0.26.2 — grok-cli headless permission-cancel fix

**WHAT:** Patch release. `skills/grok-cli/SKILL.md` updated so every headless tool-using invocation (second opinion, review, adversarial, resume — not just delegate) passes `--always-approve`. Added troubleshooting section for the failure signature. All five manifests bumped 0.26.1 → 0.26.2 via `bump-version.sh`.

**WHY:** Without `--always-approve`, headless grok runs that touch a non-allowlisted shell command resolve as `permission_cancelled`, cancelling the whole turn: exit 0, empty or one-sentence stdout, discarded parallel reads — looks like a model crash but isn't.

**HOW:** Documented that sandbox and approvals are orthogonal (`--sandbox read-only` still kernel-blocks writes even with always-approve), so read-only reviews are still safe with the flag. Updated all command patterns, the quick-reference table, and the empty-output troubleshooting entry with the `events.jsonl` diagnostic (`decision: cancelled` on `run_terminal_command`, `cancellation_category: permission_cancelled`).

**IMPACT:** Headless grok-cli second opinions and reviews now run reliably instead of silently dying mid-turn. Tagged v0.26.2.
