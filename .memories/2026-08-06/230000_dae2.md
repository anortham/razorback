## Added a release step to `scripts/bump-version.sh`

Six tags (v0.23.0 … v0.26.2) shipped without GitHub releases because publishing was a manual step nobody owned. Back-filled the six releases with `gh`, then closed the gap in the tooling.

**WHAT**
- New command: `bump-version.sh --release [version] [--dry-run] [--notes-file PATH]`.
- New config key `release.excludeSubjects` in `.version-bump.json` (seeded with `^chore: record `, `^chore\(memory\): `) drops goldfish-checkpoint commits from generated notes.
- New guard suite `tests/version-release.test.mjs` (13 tests, git fixture repo).
- README "Releasing" section and CLAUDE.md version-management bullet document the sequence.

**HOW**
- Notes come from the tagged commit's body (trailers `Claude-Session`/`Co-Authored-By`/`Signed-off-by`/`Change-Id` stripped) plus one bullet per non-merge commit back to the previous tag, oldest first. That is why the release commit message must read as the changelog entry.
- The version guard reads manifests **inside the tag** (`git show <tag>:<path>`), not the working tree. Rejected the working-tree `cmd_check` approach: it makes back-filling an older tag impossible and proves nothing about the tagged commit.
- Publish-only preconditions (clean tree, `gh` auth, tag on origin, no existing release) are skipped under `--dry-run`, which keeps the tests network-free.
- `--latest=false` unless the tag is the highest semver tag, so a back-fill cannot steal the Latest badge.
- Extracted `jq_path()` helper; replaced a `[[ ]] && var=1` line (set -e hazard) with an explicit `if`, and an array-based subject filter (set -u hazard on empty arrays under bash 3.2) with a single joined ERE.

**IMPACT**
- Releasing is now: bump → commit `release: X.Y.Z <summary>` → tag → push --follow-tags → `--release`.
- Verified: `npm test` 169/169; `--audit` clean; `--release <v> --dry-run` succeeds for all six real tags and reproduces the hand-written v0.26.1 notes nearly verbatim.
- Changes are uncommitted on `main` — the user has not asked for a commit.
