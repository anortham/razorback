## HOW — grounded in real `grok` 0.2.111 CLI surface (verified via --help + live probes)
- Headless single-turn: `grok -p "prompt"` (also `--single`); `--prompt-file <PATH>` for large prompts. Did NOT hang on stdin in testing (unlike codex), but keep `< /dev/null` as cheap insurance.
- Working dir: `--cwd <CWD>` (grok's `-C` equivalent).
- Read-only review: `--sandbox read-only` (built-in). Delegate write: `--sandbox workspace` + `--always-approve` (or `--permission-mode bypassPermissions`). Built-in profiles: read-only, workspace, none. `danger-full-access` is NOT built-in (custom-only in ~/.grok/sandbox.toml).
- Structured output: `--json-schema '<JSON STRING>'` implies `--output-format json`. VERIFIED envelope: `.structuredOutput` (parsed object), `.text` (schema JSON as string), `.usage`, `.total_cost_usd`, `.stopReason`, `.sessionId`, `.num_turns`. Strip `$schema` key defensively via jq like claude does.
- Model: `-m/--model` (default grok-4.5). Effort: `--reasoning-effort`/`--effort`. Inherit default unless user selects.
- Auth check (non-interactive): `grok models` prints "You are logged in with grok.com" + default/available models. Login: `grok login` (`--oauth`, `--device-auth`). No `auth status` subcommand.
- No ephemeral flag — sessions persist; manage via `grok sessions`, resume via `-c/--continue` or `-r/--resume`. Honest grounded difference from siblings.
- No `--ignore-user-config` equivalent — grok inherits project AGENTS.md/CLAUDE.md/skills (verified via `grok inspect`). Note independence caveat like claude.
- No native `review` subcommand (codex has one) — only unified-prompt path.
- permission-mode values: default, acceptEdits, auto, dontAsk, bypassPermissions, plan.
