## Added Batch mode: a list of small items ships on one branch, one gate, one PR

**WHAT:** `fixing-small-issues` gained a `## Batch mode` section and lost the "open a PR" line in Step 4. `brainstorming` triage, `using-razorback` Execution Model and Red Flags, `writing-plans` "When to Write a Plan File", and `finishing-a-development-branch` "Not here" now route a list of small, independent items to Batch mode. Instruction-tier rule 2 (and its five host copies) carries the one-batch sentence. Site updated. Guard test: `tests/batch-path.test.mjs`.

**WHY:** The user handed agents 11 small items and got 11 branches, 11 PRs, and 11 full-suite runs; an expected 2-hour job took all day. Root cause: the skill set had no path between "one quick fix with its own PR" and "a plan". `fixing-small-issues` Step 4 told the agent to open a PR per fix, and its cumulative escalation triggers (3rd file, 2x lines) forced any list of items toward a plan.

**HOW:** Criteria and triggers measure one item, never the branch sum. A failing item leaves the batch and routes to brainstorming alone. The full suite and slow suites run once after the last item. The batch PR gets a plain body; the morning report and its metadata commits stay with plan runs.

**IMPACT:** A backlog of small items no longer needs a plan file, worker, ledger, or report. Branch `batch-path`, full suite 512 pass / 0 fail.
