## Local release tag pruned by fetch

### WHAT
An explicit `git fetch origin` removed the newly created local `v0.49.0` tag. The release commit `4ebc9d3a6ae5d1f8c82f7744383bafc01e89a4e2` remains intact. Remote inspection shows `origin/main` at `e53a9ee` and no remote `v0.49.0` tag; the only remote release tag is `v0.48.8`.

### WHY
A broad fetch after local tagging was unsafe with this Git configuration.

### HOW
`git config --show-origin --get-all fetch.pruneTags` reports global `fetch.pruneTags=true` in `/home/murphy/.gitconfig`. No global configuration was changed. The correct recovery is to recreate the same annotated tag at the verified release commit and push the authorized branch and tag. Avoid another fetch until the tag is on origin.

### IMPACT
The recovery recreated `v0.49.0` at the verified release commit and pushed it with `main`. GitHub Actions passed for both the branch and tag. No remote tag was deleted or rewritten, and global Git configuration was left unchanged.
