## Added test-scope rule to the instruction-tier ruleset

**WHAT:** New process rule "Scope test runs" in `skills/using-razorback/references/instruction-tier.md` (rule 5, old 5–6 renumbered to 6–7), propagated to all five host copies. Added rule 7 to the `using-razorback` SKILL.md toolchain rules and to `references/subagent-toolchain.md`. Added the invariant phrase `Do not rerun a passing scope on an unchanged tree` to `scripts/check-rule-copies.mjs`.

**WHY:** Agents ran full test suites reflexively — observed in the miller repo: full fast suite before a merge, again after a clean fast-forward merge that did not change the tree. Razorback's plan-execution skills already carry the scope ladder (worker → affected-change → branch gate) and ledger reuse, but ad-hoc sessions and dispatched subagents never load those skills. The toolchain floor is the only surface every session and subagent sees.

**HOW:** The rule states: focused tests in the inner loop, broader suites at task boundaries, the full suite once at the branch gate, and never rerun a passing scope on an unchanged tree. The same fix was applied at the source in miller's CLAUDE.md/AGENTS.md Testing section, which previously said "Run this on every change" — that line was the root cause of the observed behavior, not a missing focused-test instruction.

**IMPACT:** Every harness tier (plugin bootstrap, subagent injection, instruction-tier host copies) now carries the test-scope rule. Verified: `node scripts/check-rule-copies.mjs` green, `node --test tests/rule-copies.test.mjs` 7/7 pass.
