## Pages site live at anortham.github.io/razorback + repo branch cleanup

### WHAT

PR #12 merged to `main` at `e20c04d`. The GitHub Pages site is **live and verified** at https://anortham.github.io/razorback/.

- **Site:** `docs/site/` (index.html, style.css, script.js, 404.html, .nojekyll, assets/) deployed by `.github/workflows/pages.yml`. Hand-written, no build step, no runtime dependency.
- **README:** five v0.28.0 drifts closed; Skills table is 26 rows for 26 skill directories; website link sits under the title as a blockquote, matching Miller's README convention.
- **Cleanup:** worktree `docs-site-2026-08` removed; four remote branches deleted (`worktree-docs-site-2026-08`, `worktree-security-pass`, `worktree-ponytail-adoption`, `codex/autonomous-no-stops`) — each verified to have zero commits not in `main` before deletion. Remote is now `origin/main` only.

### WHY

v0.28.0 shipped without a README update, and the user wants to recommend razorback to coworkers. A repo README is poor first contact for an adoption decision.

### HOW — deploy gating, worth remembering

Enabling Pages in repo settings was **necessary but not sufficient**. The deploy could not run until `pages.yml` existed on `main`, because Actions only runs workflows present on the pushed branch — and `workflow_dispatch` also requires the file on the default branch. The sequence is always: merge first, then the workflow fires.

Note `gh api repos/OWNER/REPO/pages` reports `"status": null` even for a healthy site. That field tracks the legacy Jekyll pipeline, which never runs for `build_type: "workflow"`. Do not read it as a failure — use HTTP fetches and a browser render as the real evidence.

### Verification of the live site

Rendered against the real host, not local files: 360px and 1280px, light and dark — no horizontal scroll, no unscrollable overflow, correct `body` background per scheme, zero console errors, **zero off-origin requests**, and 13,367 characters still visible with JavaScript disabled. All four assets return HTTP 200; an unknown path returns 404.

### IMPACT — new local capability

Added `~/.claude/bin/render-page.mjs` (Playwright, self-contained deps in that directory). One command renders any local or remote page at chosen widths in both colour schemes and reports overflow, body background, console errors, off-origin requests, and a no-JS pass. Allowlisted in `~/.claude/settings.json` alongside `firefox --headless`.

**Lesson worth keeping:** an earlier "no browser available" conclusion was wrong — the check tested for `chromium`/`google-chrome`/puppeteer and never tested `firefox`, which was at `/usr/bin/firefox` the whole time, with Playwright's Chromium already cached. Probe for the specific tool before concluding a capability is absent.
