## Visual digest designed via prototype; combined design doc written

**WHAT:** Brainstormed the visual-output feature to a settled design, validated the layout with a 3-variant HTML prototype (branch `prototype/plan-digest`, commit f4f9b64, file `prototype-plan-digest.html`), and wrote the combined design doc `docs/plans/2026-08-07-upstream-adoption-and-visual-digest-design.md` covering all three lanes: (A) 5 audit bugs, (B) 10 upstream adoptions, (C) visual digest.

**WHY:** User wants visually engaging HTML views of plans/design docs/morning reports (ADHD: visual hierarchy beats markdown walls) without the token waste of bespoke HTML everywhere; plus the approved audit-remediation cycle (option 3: bugs as batch A + adoption cycle).

**HOW:** Verdict from the user driving the prototype: Variant B (execution timeline — vertical batch spine, task rows, inline warning flags, "you are here") composited with tabs for Decisions and Guardrails. Digest is a concise view; markdown stays canonical; kit lives at `skills/using-razorback/references/digest-kit.md` (dataviz reference palette, status chips icon+label, meter/timeline/tabs/flag components); model inlines kit CSS per file.

**IMPACT:** Design doc awaiting user review — the gate before worktree + writing-plans. Prototype preserved as primary source; main clean except .memories and the design doc.
