## Design approved: opencode dual-harness support

Wrote spec at `docs/plans/2026-04-12-opencode-dual-harness-design.md` for adding first-class opencode support alongside Claude Code.

### WHAT
- Modernize `.opencode/plugins/razorback.js`: add `config` hook to register `skills/` dir (kills symlink requirement), replace `experimental.chat.system.transform` with `experimental.chat.messages.transform` (fixes token bloat + Qwen breakage).
- Harness-branched bootstrap: Claude Code primary = team-driven, opencode primary = subagent-driven.
- Un-deprecate `subagent-driven-development` skill; refresh for current razorback conventions (Julie-first, inline review by lead).
- Add `.opencode/INSTALL.md`, root `package.json`, `AGENTS.md` → `CLAUDE.md` symlink.
- Update README and `docs/README.opencode.md` for current v0.6.x state.

### WHY
User runs opencode with non-Claude models. Existing v0.5.0 opencode integration predates v0.6.0 Agent Teams, uses a deprecated hook pattern, and forces manual symlinks.

### HOW
Port superpowers' current plugin pattern (reference: `~/source/superpowers/.opencode/plugins/superpowers.js`). User confirmed Option A (revive subagent-driven) over Option B (route to dispatching-parallel-agents + executing-plans pair).

### IMPACT
Once implemented: one-line opencode install via git+https, no symlinks, correct execution-model guidance per harness, no Claude Code regressions. Next harnesses (Cursor, Codex, Gemini) explicitly out of scope.
