## Codified the after-failure test loop across razorback skills (branch test-scope-loop)

**WHAT:** 
- Canonical procedure in `skills/systematic-debugging/SKILL.md`: Phase 1.2 (a failing run is the reproduction; capture its output to a file on the first run; list every failing id; reproduce with those ids through the runner's own filter; never rerun the wide command to re-read or to find the next failure) and Phase 4.3 (ids until green, affected scope once, wide command once on the changed tree). New red-flag row and "It's working if" line.
- Floor rule (using-razorback rule 7, instruction-tier rule 5, subagent-toolchain rule 7): "Do not rerun any scope on an unchanged tree" (was "a passing scope") + capture-to-file + failing-id loop. Five host copies synced; `check-rule-copies.mjs` invariants 9 → 10; session-start test count pin updated.
- Pointers: TDD Verify RED (run only the new test, runner narrowed with its own filter) and Verify GREEN (assigned scope once on the final tree; on scope failure, ids then scope once); finishing Step 1 + stranded row + interactive-mode fast-forward gate; fixing-small-issues Step 4; SDD implementer prompt (split red/green vs ceiling fields; "never invent a runner", narrow with its filter) and fix prompt; pre-merge fix-dispatch-prompt; verification-before-completion evidence row + 2 rationalization rows; receiving-code-review per-item tests; verification-scopes worker-ceiling "once on the final tree"; task-templates acceptance line; plan reviewer Verification row; brainstorming lightweight doc; cursor-agent contract; writing-skills scoped re-test; root-cause-tracing no longer hard-codes `npm test`.
- Guard test `tests/test-scope-loop.test.mjs`.

**WHY:** User report: agents run the full suite, see a failure, make a small change, rerun the whole suite. RED fixture runs showed the worker path already narrows; the lead path's real waste was rerunning a failing wide run on an unchanged tree to re-read output (4/7 at medium/low effort) — the old rule only covered passing scopes.

**HOW:** writing-skills RED → GREEN with the Workflow tool: 12 RED runs + 5-reader sweep with 192 skeptic verdicts, then 7 GREEN runs on the same fixtures. GREEN: 0 wide reruns on unchanged trees, final wide run present in every gate scenario, worker/CI scenarios unchanged.

**IMPACT:** `npm test` 423/423. Ready to commit and PR. Not tested: Codex/OpenCode-hosted agents (would spend OpenAI credit), suites with truncated tool output (the capture rule targets that case by design).
