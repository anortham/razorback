## RED baseline for the full-suite rerun loop (brief: inner-loop-test-isolation)

**WHAT:** Ran 12 real fixture scenarios (node --test repo, 27 s serial suite) under the current 0.40.0 skill text, plus a 5-reader sweep of every skill file with a skeptic verdict per finding (192 verdicts).

**Findings from behavior (Opus 5):**
- Worker path (SDD implementer prompt + TDD, 5 runs incl. plan scope `npm test` and no narrowing docs): every worker narrowed to one file per RED/GREEN cycle and ran the wide scope at most once at the end. The loop does not come from the worker path.
- Lead path on a red branch gate (3 root causes across 4 files; finishing / ad-hoc "run the tests and fix" / executing-plans; xhigh, medium, low effort): all 7 narrowed per fix. The waste that did appear, in 4 of 7 (all medium/low): **rerunning the full suite on an unchanged tree to re-read output** the agent had piped away (tail/grep). One low-effort run skipped the final wide run entirely.
- Agents cite using-razorback rule 7 for narrowing; the rule says "do not rerun a *passing* scope on an unchanged tree", so a failing wide run got rerun to re-read it.

**Findings from the sweep (confirmed real, non-neutral, 26):** finishing Step 1 "rerun the failed scope" (ambiguous per-attempt), finishing stranded row "rerun Step 1" per item, interactive-mode post-merge gate on a fast-forward, receiving-code-review "test each" / "verify no regressions" per fix, root-cause-tracing hard-codes `npm test` per instrumentation pass, implementer-prompt one scope field for red/green and ceiling, verification-scopes worker-ceiling has no "when", task-templates "Tests pass" unscoped, plan reviewer never checks the Verification Strategy, writing-skills "revise and re-test" unscoped, cursor-agent verification list unscoped, brainstorming lightweight doc has no verification scope, no binding after-failure procedure anywhere (systematic-debugging reproduce/verify and verification-before-completion gate are the slots).

**WHY:** writing-skills Iron Law: no edit without a failing run first.

**HOW:** Workflow tool; fixture at scratchpad/runs/red-*; results in scratchpad/red-runs.json, red-gate-runs.json, red-sweep.json.

**IMPACT / decision:** Canonical home for the after-failure procedure = systematic-debugging (Phase 1 reproduce + Phase 4 verify), compact form in the three synced floor files (rule 7 / instruction-tier rule 5, invariant updated to "on an unchanged tree" + capture-to-file), one-line pointers in TDD, finishing, fixing-small-issues, SDD prompts, pre-merge fix prompt, verification-before-completion. GREEN = rerun the medium/low gate scenarios and one worker scenario under the edited text.
