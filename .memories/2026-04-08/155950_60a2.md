## Razorback Revival Design Complete

Brainstormed and designed the strategic direction for razorback v0.6.0+.

### Key Decisions
- **Diverge intentionally** from superpowers (share DNA, make own choices)
- **Team-first execution model**: Replace `subagent-driven-development` with `team-driven-development` using Claude Agent Teams
- **Keep the full ceremony** (brainstorm, plan, TDD, execute, review, finish) but optimize each step for token efficiency
- **Cherry-pick v5 wins**: inline self-review, continuous execution, 3-iteration review cap
- **Skip v5 bloat**: multi-platform support, visual brainstorm companion, brainstorm server
- **Julie handles cold-start**: Phase 1 leans on Julie's get_context/deep_dive to compress agent orientation. Phase 2 will explore context sharing patterns.

### Why Teams Over Subagents
- Teammates persist, so fixes don't require cold-restart (the v0.4.0 fix-prompt.md problem solved natively)
- Parallel implementation is the primary use case
- Lead does inline review (not reviewer subagents), cutting review cost from 25 min to 30s
- Teammates can communicate directly (mesh topology vs star)
