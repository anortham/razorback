## Audited codex-cli and claude-cli skills against live CLI versions

Verified both reference skills against installed CLIs (codex-cli 0.143.0, Claude Code 2.1.204) and fixed drift.

### Findings fixed
- **codex 0.143 removed `-a/--ask-for-approval` from `codex exec`** — the skill's delegate flow (`--sandbox workspace-write -a never`) errored with `unexpected argument '-a'`. Updated Defaults, Delegate section, Error Handling, and Quick Reference to `--sandbox workspace-write` alone; noted `-a` remains valid on interactive `codex` only. `--full-auto` still parses on exec (deprecated).
- **codex `goals` feature is now stable + enabled by default** (`codex features list`: `goals stable true`) — updated Quick Reference row and `references/follow-goals.md` (re-verified 2026-07-08).
- **`claude -p` blocks on stdin EOF even with a prompt argument** — empirically proven (held-open pipe delayed the answer by exactly the pipe lifetime). Same Windows hang class as codex. Added `< /dev/null` / `< NUL` guidance to Defaults, all five command snippets, Error Handling, and Quick Reference of claude-cli skill.
- **`--max-turns`, `--system-prompt-file`, `--append-system-prompt-file` are hidden from `claude --help` but still supported** (missing-argument parse probe vs unknown-option control). Documented so future audits don't strip them.
- Minor: `--fallback-model` now takes a comma-separated list with per-turn primary retry; `claude auth status` gained `apiProvider` field; `codex review` top-level = `codex exec review` with `--title`.

### Verification
- GREEN run of both updated recipes: `codex exec --sandbox workspace-write` and `claude -p ... --max-turns 2 < /dev/null` both returned `ok`, exit 0.
