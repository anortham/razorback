## Made skill cross-references harness-agnostic

Skills across razorback hardcoded `team-driven-development` as the primary parallel-execution path, but that skill depends on Claude Code Agent Teams and does not exist in opencode. Opencode users following those references lost subagent delegation and ended up doing work in the main agent, blowing context.

**Research finding:** opencode does support parallel subagent dispatch. It has a `Task` tool (analogue of Claude Code's Agent tool), and the built-in `general` subagent description explicitly says "Use this to run multiple units of work in parallel." Subagents run in isolated child sessions. The real gap vs. Agent Teams is **teammate persistence** (opencode Task invocations are always fresh), not parallelism.

**Design chosen:** match upstream superpowers pattern. Skill bodies reference `subagent-driven-development` as the canonical plan-execution path. `team-driven-development` stays a Claude-Code-only upgrade promoted by the using-razorback bootstrap Execution Model (which the opencode plugin already rewrites to point at subagent-driven).

**Changes:**
- `subagent-driven-development/SKILL.md` — documents parallel dispatch (Task tool fan-out), harness-aware fix routing (resume on Claude Code, fresh dispatch with commit pointers on opencode)
- `brainstorming`, `writing-plans`, `requesting-code-review`, `dispatching-parallel-agents`, `using-git-worktrees`, `finishing-a-development-branch`, `executing-plans` — all now reference subagent-driven-development as the primary plan-execution path
- `using-razorback` and `team-driven-development` — unchanged (Claude Code bootstrap still promotes team-driven as primary; opencode plugin rewrites it)

Design doc at `docs/plans/2026-04-15-harness-agnostic-skill-references-design.md`.

**IMPACT:** opencode users invoking any planning/execution skill now get pointed at a skill that actually exists in opencode and supports parallel subagent dispatch. Main-agent context bloat from non-delegated work should drop.
