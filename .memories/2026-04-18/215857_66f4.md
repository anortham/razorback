## Clarified Codex CLI vs desktop app support

### WHAT
Ran a second documentation pass so Razorback's Codex guidance now distinguishes between:

- Codex as a harness, meaning CLI and desktop app sharing native skill discovery
- The desktop app's built-in agent tools (`spawn_agent`, `send_input`, `wait_agent`, `close_agent`)
- The separate `razorback:codex-cli` skill, which launches an external Codex CLI process for reviews or delegation

Updated files:

- `.codex/INSTALL.md`
- `docs/README.codex.md`
- `skills/using-razorback/SKILL.md`
- `CLAUDE.md` (via the `AGENTS.md` symlink)
- `skills/using-razorback/references/codex-tools.md`

### WHY
The prior pass fixed the stale Codex agent lifecycle docs, but the higher-level install and bootstrap docs still sounded CLI-only. That left an awkward gap: the desktop app clearly exposes the same subagent controls, but the repo did not say so plainly.

### HOW
- Broadened install/readme language from "Codex" or implicit CLI wording to explicit "Codex CLI or desktop app"
- Added a desktop note in `docs/README.codex.md` explaining that the same agent lifecycle applies in desktop sessions exposing the built-in agent tools
- Clarified that `razorback:codex-cli` is an external reviewer/delegation skill, not the desktop app's built-in agent mechanism
- Updated the top-level harness docs in `CLAUDE.md` to label Codex as `CLI + desktop app`
- Re-ran targeted grep checks and `git diff --check`

### IMPACT
A user reading the Codex docs now gets the right mental model:

- install path and skill discovery are shared between CLI and desktop
- long autonomous runs rely on Julie + Goldfish in both cases
- Codex desktop app is a first-class harness for Razorback's subagent-driven execution, not an unsupported side path
- `codex-cli` remains useful, but it is clearly framed as an external second-opinion/reviewer tool
