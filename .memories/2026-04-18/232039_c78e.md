## Removed broken `--bare` guidance from the Claude reviewer path

### WHAT
- Rewrote the active `claude-cli` skill guidance to stop using `--bare` in command examples.
- Updated the pre-merge Claude reviewer prompt and summary docs to use the auth-compatible `claude -p` invocation.
- Added a Node test at `tests/claude-cli-docs.test.mjs` that fails if active Claude command blocks reintroduce `--bare` or if the README regresses.

### WHY
- Current Claude CLI help says `--bare` skips OAuth and keychain auth reads.
- The previous skill text treated `--bare` as the default isolated mode, which breaks the common Anthropic login path and causes the skill to fail in practice.

### HOW
- Verified the root cause with `claude -p --help` and `claude auth status`.
- Wrote a failing regression test first, then updated the skill docs and reviewer prompt to remove `--bare` from runnable commands while leaving a short warning about why the flag is avoided.
- Re-ran the test suite and a live `claude -p --no-session-persistence --dangerously-skip-permissions --tools "Read,Bash" --model opus` smoke check.

### IMPACT
- Future agents should stop copying a broken Claude invocation from razorback's active docs.
- The pre-merge Claude reviewer path now matches a command shape that works with the normal OAuth login flow.
- The new regression test should catch any future attempt to slide `--bare` back into active command blocks without discussion.
