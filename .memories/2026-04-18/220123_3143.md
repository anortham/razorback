## Prepared Codex support pass for release

### WHAT
Captured the completed Codex support/documentation pass and the final repo hygiene change before release.

- Clarified that Codex CLI and Codex desktop app share Razorback's native skill discovery path
- Fixed Codex subagent lifecycle docs to match the current tool surface (`spawn_agent`, `send_input`, `wait_agent`, `close_agent`)
- Kept Claude Code on Agent Teams and OpenCode/Codex on subagent-driven execution
- Added `.codex/config.toml` to `.gitignore` so machine-local MCP config does not pollute repo status

### WHY
The project had the right broad idea for Codex, but a few stale docs would have handed Codex the wrong control flow during an autonomous run. The local `.codex/config.toml` also should never be committed because it hardcodes workstation paths.

### HOW
- Updated shared harness docs and Codex-specific install/readme files
- Verified wording against the live desktop app tool surface and local Codex CLI feature/help output
- Added a targeted ignore entry for `.codex/config.toml`
- Prepared the repo for a version bump and push

### IMPACT
The release now has a coherent story for the three main harnesses you use:

- Claude Code: Agent Teams
- Codex CLI/Desktop: subagent-driven execution with correct agent lifecycle docs
- OpenCode: subagent-driven execution without Claude-only leakage

The working tree is also cleaner because local Codex MCP config is ignored instead of showing up as a fake project change.
