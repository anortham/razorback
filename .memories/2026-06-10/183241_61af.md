## Audited and fixed cursor-agent skill (post-0.16.2 review)

### WHAT
- Reviewed `skills/cursor-agent/SKILL.md` (shipped in 0.16.2) against the real `cursor-agent` CLI and razorback conventions; fixed three defects.

### WHY
User asked to verify the new Cursor skill is correct and optimized. The skill was authored in a Codex session and hardcoded "Codex" as the lead, but razorback skills are shared across all six harnesses.

### HOW
- **Harness-neutral lead language:** replaced all "Codex" references with "the lead" / "the dispatching agent" in the skill, the safety block, and the subagent-driven-development pointer. Test now guards with `doesNotMatch(/\bCodex\b/)`.
- **`--trust` vs `--force` split:** verified against `cursor-agent --help` that `--trust` only suppresses the workspace-trust prompt (needed on ALL headless `-p` runs, including read-only `--mode ask`), while `--force` is the command-permission bypass. The old text conflated them and omitted `--trust` from the read-only quick-reference row, which would stall headless.
- **Removed broken `cursor-agent ls` advice:** verified `ls`/`resume` are interactive Ink TUIs that error with "Raw mode is not supported" in non-interactive shells. Skill now requires `create-chat` up front and warns against `ls`/`resume`.
- Verified `composer-2.5-fast` exists via `cursor-agent models` (it is Cursor's default model).

### IMPACT
Skill now works when Claude Code, Gemini, or any non-Codex lead delegates to Composer; headless read-only runs no longer stall on the trust prompt; the fix loop no longer depends on an interactive-only command.
