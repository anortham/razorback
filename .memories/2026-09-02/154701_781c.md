## Codex read-only sandbox failure: root cause and wrapper fix

**WHAT**
- Added `skills/codex-cli/scripts/codex-exec`, a bash wrapper around `codex exec`. On Windows it puts the MSI pwsh first on PATH when PATH resolves the Microsoft Store pwsh, probes `codex sandbox -- <pwsh> -NoProfile -Command exit`, and exits 2 with no model turn if the probe fails. Off Windows it is a pass-through.
- All codex-cli recipes and Quick Reference rows, plus the pre-merge codex reviewer prompt, dispatch through the wrapper.
- Rewrote the Windows sandbox notes in codex-cli (Defaults, Error Handling, Quick Reference) with the real cause. Added a preflight bullet to pre-merge codex.md error handling and a sentence to managing-review-campaigns: a preflight refusal consumes no invocation.
- New guard test `tests/codex-sandbox-preflight.test.mjs` (wrapper behaviour with a fake codex, plus doc shape). Updated `tests/pre-merge-review-isolation.test.mjs` to expect the wrapper.

**WHY**
`CreateProcessAsUserW failed: 5` is not a GPO sandbox block. Codex resolves `pwsh` via PATH; Windows Terminal runs the Store pwsh and prepends its WindowsApps package dir to child PATH. The WindowsApps ACL denies the restricted sandbox token. `codex sandbox` proved it: Store pwsh fails, MSI pwsh and PowerShell 5 run. `codex exec -s read-only` with MSI pwsh first on PATH read files normally. The old `-s danger-full-access` fallback dropped sandboxing and only applied after a burned invocation.

**HOW**
Systematic debugging: reproduced with a minimal codex call, isolated the shell path with `codex sandbox`, confirmed the PATH-prefix hypothesis end to end, then wrote the failing test before the wrapper. Wrapper chosen over an inline preflight snippet so recipes cannot forget it.

**IMPACT**
- Codex review and delegate flows work sandboxed on this host again (verified end to end through the wrapper, version read back).
- Full suite: no new failures vs a clean HEAD baseline worktree (65 pre-existing Windows environment failures in export/redaction script tests remain on this host).
- Installed plugin copies (0.37.0 cache, ~/.agents/skills/razorback, ~/.codex/razorback) still carry the old text until the next release.
- User PATH edits cannot fix the host; only the Windows Terminal profile (MSI pwsh) can.
