## Generalized Codex quiet-wait guidance to all external model CLIs

- **WHAT:** Broadened the Codex waiting guidance in `skills/using-razorback/references/codex-tools.md` from Cursor-only to all external model CLI skills: `cursor-agent -p`, `claude -p`, `codex exec`, and `gemini -p`. Updated `tests/cursor-agent-skill.test.mjs` so the regression covers the whole class.
- **WHY:** Auditing the skills showed that `claude-cli`, `codex-cli`, `gemini-cli`, and `pre-merge-review` reviewer prompts all launch long-running model CLIs. They already contain generous timeout guidance, but they did not address Codex's shell-session behavior where control can return to the lead before the external CLI exits, causing frequent polling and speculative progress updates.
- **HOW:** Kept the fix centralized in the Codex tool mapping instead of duplicating it across every CLI skill. The new rule tells Codex leads to run external model CLIs as foreground commands, avoid elapsed-time narration/speculation, avoid speculative progress updates, poll no more often than every 2 minutes, and prefer empty `write_stdin` waits such as `yield_time_ms=300000` when the shell tool returns a running session.
- **IMPACT:** Covers Cursor Agent plus Claude CLI, Codex CLI, Gemini CLI, and pre-merge reviewer invocations from Codex with one harness-specific policy.
