## Added Codex quiet-wait guidance for Cursor Agent

- **WHAT:** Added Codex-specific guidance in `skills/using-razorback/references/codex-tools.md` for `razorback:cursor-agent` runs, plus a regression test in `tests/cursor-agent-skill.test.mjs`.
- **WHY:** The shared `cursor-agent` skill correctly says Cursor is a bounded implementation worker, but Codex-specific long-running shell behavior was undocumented. Codex can return a running session before `cursor-agent -p` exits, which led the lead model to poll frequently and speculate about elapsed time.
- **HOW:** Kept `skills/cursor-agent/SKILL.md` harness-neutral, consistent with the existing test that forbids hard-coded Codex language there. Put the waiting policy in the Codex tool mapping: run Cursor as a foreground command, do not narrate elapsed time, do not send speculative progress updates, and poll no more often than every 2 minutes using empty `write_stdin` waits such as `yield_time_ms=300000` when the harness forces a session check.
- **IMPACT:** Future Codex leads using `razorback:cursor-agent` should launch Cursor, wait quietly, and review the final output/diff after exit instead of burning usage with frequent progress checks.
