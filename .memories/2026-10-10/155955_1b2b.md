## Plan pivots: a plan binds outcomes and contracts, not steps

**WHAT:** On branch `feat/plan-pivots` (uncommitted):
- `writing-plans` drops the Full/Light plan depths for a single task template. A new "What a Plan Binds" section says what is binding: the Goal, acceptance criteria, Interfaces, Contract inputs, file ownership, Global Constraints, and approved architecture. A task's Approach is not binding.
- `executing-plans` Step 2.3 no longer says "follow the plan's steps exactly". The implementer prompt has a new Approach section and no longer says "Implement exactly the task".
- The blocker taxonomy adds "a better approach" as a decide-and-log case. SDD review accepts a logged better approach.
- Test guards, README, `docs/site`, `CLAUDE.md`, and the plan reviewer prompt were updated to match.

**WHY:** In the RED baseline, Opus and Haiku both kept the worse plan Approach. P1 had four copies of the retry logic instead of one change in a shared helper. P2 used a hand-written regex while the repo already uses date-fns. The rules that forced this were "Follow the plan's steps exactly", "Implement exactly the task", "Do not redesign locally", and Candidate Mode.

**HOW:** The executor takes a better way only when it keeps every binding part and changes no behavior outside the task (other callers, error cases). It logs the choice as `file:line - chose X over Y because Z`. When a better way would change a binding part, the executor follows the plan and proposes the change in the report. "Do not redesign locally" stays, scoped to the approved module/interface shape.

**IMPACT:** In the GREEN runs, both models took the better path in P1 and P2 and kept the contract in P3. In P4, where a shared helper also serves a fail-fast healthCheck, Haiku correctly did not change that helper.
