## Model-capability evaluation of razorback; self-validation skill added

**WHAT:** The skills were checked against current models (Opus 5.5 era). A new skill, `building-feedback-loops`, was added on branch `feat/self-validation-loop`. The change is uncommitted. It also adds a "Feature works" row to the evidence table in `verification-before-completion`, plus README and `docs/site` entries (skill count is now 31).

**WHY:** In the RED baseline, without the skill, both Opus and Haiku already ran the real app when a run path existed. When none existed (a webhook service with no run script), both skipped the run and gave the check back to the user. Haiku also wrote the payload from memory, and both models left their sample data in the scratchpad. With the skill loaded, both models built a fake upstream on localhost and a fixture, and kept the loop in the repo.

**HOW:** The skill was written test-first under `writing-skills`: RED and GREEN on Opus and Haiku, then a REFACTOR pass. That pass added a fallback for unreachable fixture sources, the MCP browser checks that leave no file, and `browser_console_messages`. The skill is about 600 words. It points to the external design skills (`frontend-design`, Impeccable, Vercel `web-design-guidelines`) and does not copy them in.
