## WHAT

Hardened Razorback's autonomy contract across brainstorming, blocker handling, security review, pre-merge review, branch finishing, and subagent-driven development. Added regression guards and marked every acceptance criterion complete in the approved design.

## WHY

Recent workflow changes left five ways for agents to pause unnecessarily: routine brainstorming questions, unconditional reviewer allowlists, first-run security failures, stale single-pass language, and ambiguity about whether a goal runner was required. Long-running autonomous execution remains the top workflow priority.

## HOW

- Made the blocker taxonomy explicitly goal-independent: `/goal` and `/loop` add persistence but are never prerequisites.
- Required agents to diagnose, repair, and rerun recoverable security and branch-gate failures while a safe plan-consistent path exists.
- Preserved hard security gates and made external-review allowlists conditional on an actual policy block.
- Scoped brainstorming stops to unresolved material decisions, leaving routine reversible details to agent judgment.
- Corrected subagent-driven development to describe its general plus security review passes.
- Used TDD: five focused contract tests failed before implementation and all focused tests passed after it.
- Completed lead spec and architecture review, then corrected the only review finding: unchecked acceptance markers in the design.

## IMPACT

Agents now continue through ordinary ambiguity and recoverable failures without requiring a goal or needless user input. Real safety, authorization, product-intent, access, and exhausted-diagnostic blockers still stop execution. No hard security gate was weakened.
