## Cohesion sweep across the skill set

Checked the whole skill set for consistency after the 0.29.x reviewer changes. Three real gaps, all fixed.

### Fixed

- **The no-caps policy lived in only one of three sibling skills.** `claude-cli` had a Defaults bullet stating it; `grok-cli` buried it in an error-handling entry and `codex-cli` never stated it. Added a parallel "No caps in review recipes" Defaults bullet to both, worded for each CLI's actual flag surface (grok names `--max-turns`; codex states the policy generally since it has no such flag).
- **`review-targeting.md` contradicted the new timeout framing.** Its background-mode message told users a large review "can take 2-5 minutes" while error handling now says 10-20+ minutes is normal — a lead would think a healthy run was stuck at minute 8. Updated to 10-20+, plus an explicit statement that the heuristic picks where output lands and never narrows what the reviewer sees.
- **Guard test extended:** new case in `tests/reviewer-uncapped.test.mjs` asserting all three CLI skills carry the no-caps bullet, so the policy can't drift back to living in one file.
