## Removed the turn cap too — reviews now run uncapped

Follow-up to the `--max-budget-usd` removal. The user rejected `--max-turns 15` on the same grounds: any cap can truncate a review and cost more in missed findings than it saves.

- **Removed `--max-turns 15` from:** `skills/claude-cli/SKILL.md` (both review commands, hidden-flag note, `--help` probe example, quick-reference table), `skills/pre-merge-review/reviewer-prompts/claude.md` (dispatch command, validated-baseline flag list, rationale), `skills/pre-merge-review/SKILL.md`, `skills/grok-cli/SKILL.md` (both commands, quick-reference table).
- **Blocker taxonomy:** the "turn cap trips" and "budget cap trips" unavailability triggers are gone. Replaced with a **Bash timeout** trigger that explicitly says do NOT add `--max-turns` to make a run finish sooner.
- **Only remaining bound on a review is the Bash timeout** (10–30 min depending on diff size).
- **Anti-drift notes** now live in claude-cli Defaults, the grok-cli "max turns reached" error entry, and the reviewer-prompt flag rationale, so neither flag creeps back.
- `tests/claude-cli-docs.test.mjs` still contains `--max-turns` inside synthetic drift fixtures for the `--tools` scanner. Those are fixtures, not recipes — left alone.

**Verified:** `npm test` — 224 pass, 0 fail. `git diff` confirms every command block keeps its backslash continuations.

**Impact:** external review depth is bounded only by the timeout. Uncommitted on `main`.
