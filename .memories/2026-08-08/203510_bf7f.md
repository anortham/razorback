## Added source-control hygiene checks across the worktree/branch lifecycle

Razorback skills prescribed worktree *creation* well but never audited outstanding worktree/branch state. Two real failures resulted: a phase-2 worktree created beside a phase-1 worktree whose work never merged, and runs reporting "plan complete" with commits stranded off the PR branch.

### Root causes found
- **`using-git-worktrees` Step 0 was creation-blind.** It detected only "am I inside a worktree", never inventoried siblings or unmerged branches.
- **`finishing-a-development-branch` cleanup was dead code.** Step 5 gated worktree removal on the path lying under `.claude/worktrees/` — a Superpowers leftover. `using-git-worktrees` creates at `.worktrees/`, `worktrees/`, or `~/.config/razorback/worktrees/<project>/`. None matched, so razorback's own worktrees were always classified "belongs to the user" and never removed. Live proof on this machine: a fully merged, stale worktree at `~/.config/razorback/worktrees/razorback/worktree-autonomy-hardening-2026-08`.
- **Autonomous Mode never touched worktree/branch disposition at all** — Steps 1-8 pushed, PR'd, reported, exited.
- **`verification-before-completion` had no source-control row** — it proved tests/build/requirements, never integration.

### Approach
New reference `skills/using-razorback/references/source-control-hygiene.md` defines two checks, deliberately non-prescriptive about branching policy:
- **Check A — inventory before you create.** Classify every sibling worktree/branch (landed / unmerged / dirty / user's). Rule is **disclosure, not prohibition**: stranded work does not forbid a new worktree and is explicitly **not** a blocker-taxonomy stop; creating one *silently* is the bug. Prefers continuation over a sibling cut from the base (which cannot see the earlier phase's code).
- **Check B — reconcile before you claim done.** Status every worktree, `git log --oneline <base>..<branch>` per branch. Land it or name it.

Wired in: `using-git-worktrees` Step 0b + red flags; `finishing-a-development-branch` Step 2a (autonomous) / Step 6 (interactive) + fixed provenance rule; `morning-report-template.md` new `## Source control` section; `verification-before-completion` two new claim rows; `executing-plans` Step 4 and `subagent-driven-development` Step 5 reconcile before handing off.

Rejected a hard rule ("always merge phase N before phase N+1") — the user explicitly did not want prescribed branching policy, and phases legitimately stack.

### Impact
The agent now always *states* source-control state rather than assuming it. The dead cleanup path works for the locations razorback actually uses. 8 new guard tests in `tests/source-control-hygiene.test.mjs`, including a negative assertion that `.claude/worktrees/` never returns.
