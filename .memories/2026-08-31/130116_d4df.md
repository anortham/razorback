## Fixed the mechanical cause of *-cli review failures

The reviewer skills were correct as documents and unrunnable as scripts.

### WHAT

Added a `## Running These Recipes` section to `claude-cli`, `codex-cli`, `grok-cli`, and `cursor-agent`, placed ahead of the first `$SKILL_DIR` use. Added `tests/recipe-execution.test.mjs` to guard the ordering, the one-shell rule, and preamble sync across the four copies.

### WHY

Two defects made the review recipes fail in normal use:

- **Split shells.** Each recipe is one script cut into `Step 1`/`Step 2`/`Step 3` fences that share `$REVIEW_ROOT`, `$PAYLOAD_FILE`, `$REVIEW_PROMPT_FILE`, and `$SCHEMA_JSON`. Every harness Bash call is a fresh shell. An agent that ran the steps as separate calls got empty variables, so the CLI received an empty prompt or a helper path beginning `/../`.
- **Anchor defined after use.** All four skills used `$SKILL_DIR` in Step 2 but only explained it in Step 3. `cursor-agent` never explained it at all. An empty `$SKILL_DIR` makes `redact-outbound` unreachable, and the recipe exits with `outbound redaction failed`.

### HOW

One duplicated block per skill, matching the house convention for test-guarded duplication. It states the one-shell rule, sets `SKILL_DIR` and `set -u` as the first two lines of the run, and explains why a partial run is worse than a failed one. `set -u` turns a missing variable into a stop instead of a truncated outbound payload.

The pre-existing `reviewer-prompt-assets` guard checked the same anchor rule but only for `pre-merge-review/reviewer-prompts/*`, and it never checked ordering. That is why 344 green tests hid a defect in every reviewer entry point.

### IMPACT

The branch is now the better state on this axis than main, which carries both defects in all four skills. Local gates are clean at 353/353.
