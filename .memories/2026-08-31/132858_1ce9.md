## Grok's review failure was `--json-schema`, not payload size

### WHAT

Rewrote the Grok code-review and adversarial recipes as two passes: a free-form
review that keeps the agent loop, then a resume of the same session that asks
only for the schema. Hardened `validate-review-output` and replaced the dead
`SESSION_CREATED` flag with a named session id.

### WHY

Verification against real xAI calls disproved the earlier conclusion. Under
`--json-schema` Grok emits conforming JSON on its first turn and stops — 1 turn,
no tool calls, no findings — and fills the completion fields with intent:
`review_completed: true`, a future-tense summary, and the review bundle itself
cited as the only inspected file and only evidence. This happened at 384 bytes
and at 933 bytes, artifact and inline. Payload size was never the cause. The
0.35.0 artifact transport works correctly and fixed a failure that did not exist.

### HOW

- Review pass: no `--json-schema`, `--sandbox workspace`, `--tools "Read,Grep,Glob"`, `--session-id`.
- Structuring pass: `-r "$REVIEW_SESSION_ID" --json-schema`. One turn is correct there — the review is already in context.
- A review pass returning `num_turns < 2` is now a failed invocation.
- Validator rejects a review citing only `.razorback-review/`, and reads the last JSON object when `.text` holds one per turn. It previously called every multi-turn envelope malformed.
- `--session-id` replaces the flag that was set unconditionally and checked in unreachable code.

Also found: `--sandbox read-only` and `--sandbox strict` refuse to start on this
host because the container-runtime deny list cannot resolve `/run/podman`, which
is root-only. `workspace` plus the tool allowlist is a better recovery than the
`--sandbox off` the skill used to name as the only option.

### IMPACT

Grok reviews complete now, proven end to end for $0.05. Claude is unaffected —
4 turns and an accepted review under the same schema.
