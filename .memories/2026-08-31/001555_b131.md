## WHAT

Fixed all three Grok CLI skill defects confirmed by the external Grok review.

- Removed stderr suppression from every documented headless Grok invocation in `skills/grok-cli/SKILL.md`.
- Corrected the Grok 1.0.13 built-in sandbox profiles to `off`, `workspace`, `devbox`, `read-only`, and `strict`.
- Added fail-closed handling for sandbox startup failures, including runtime-socket, Podman socket, denied-path, and bwrap failures.
- Added focused documentation guards in `tests/grok-cli-docs.test.mjs`.

## WHY

The prior skill hid startup diagnostics with `2>/dev/null`, documented stale profile names, and gave no safe response when the read-only sandbox could not initialize. That caused a real authenticated Grok review to appear broken and left fallback behavior undefined.

## HOW

The skill now preserves stderr while keeping stdout/JSON usable. A sandbox startup failure closes the current review campaign because the failed CLI call consumes its invocation. Only a new, explicitly user-approved campaign may use `--sandbox off`, with a warning that kernel filesystem and child-network enforcement are disabled and with the application-level `Read,Grep,Glob` allowlist. Automatic same-campaign retry was rejected because it would violate campaign accounting and silently weaken isolation.

## IMPACT

Grok startup failures are visible and correctly classified, profile guidance matches Grok 1.0.13, and any unsandboxed fallback is explicit, isolated to a new campaign, and constrained as far as the CLI permits. Focused tests pass 8/8 and the full repository suite passes 284/284.
