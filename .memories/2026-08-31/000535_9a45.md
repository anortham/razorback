## Grok reviewed the grok-cli startup guidance

**WHAT:** Ran Grok 4.6 against `skills/grok-cli/SKILL.md` after the documented `--sandbox read-only` recipe failed before session creation. Grok found three verified instruction defects.

**WHY:** The read-only sandbox could not resolve the denied `/run/podman/podman.sock` path because of host permissions. Every documented headless recipe redirected stderr, so the only useful error vanished.

**HOW:** A user-approved fresh campaign used `--sandbox off` with only `Read,Grep,Glob`. Lead verified Grok's findings against Miller, `tests/grok-cli-docs.test.mjs`, and Grok 1.0.13 local docs. Accepted fixes: capture stderr and show it on failure; add runtime-socket/bwrap startup classification; replace stale built-in `none` with `off` and document `devbox`/`strict`. Lead rejected automatic fallback inside the same campaign because every failed CLI call consumes the immutable invocation budget. A fallback requires a new explicit campaign.

**IMPACT:** Current grok-cli guidance can turn a clear fail-closed sandbox error into an apparent silent model death, and its named unsandboxed fallback is invalid on 1.0.13. No repository implementation files changed.
