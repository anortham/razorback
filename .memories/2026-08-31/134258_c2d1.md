## Codex never reached the model — the schema was rejected

### WHAT

Added `skills/codex-cli/scripts/openai-schema`, which strips the JSON Schema keywords OpenAI structured outputs reject. Wired it into both `--output-schema` call sites: the codex-cli adversarial recipe and the pre-merge codex reviewer prompt.

### WHY

Codex does not share Grok's one-turn collapse. Its failure is earlier and total: OpenAI rejects the canonical schema with HTTP 400 `invalid_json_schema` because `uniqueItems` is not permitted. `minItems`, `minLength`, and `minimum` fail the same way once `uniqueItems` is removed. `uniqueItems` arrived in `90a90bf` during the Linear hardening batch, so every schema-constrained Codex review has failed since 0.35.0 — before the model ran, with no output at all.

### HOW

Sanitize for Codex only, rather than weakening the shared schema. Claude and Grok accept the canonical file, so it keeps its full expressiveness there. Nothing is lost on the Codex path: `validate-review-output` already enforces every stripped constraint on the returned object, including uniqueness of `files_inspected`. A guard test fails if any skill hands the canonical `.json` path to `--output-schema` again.

### IMPACT

All three external reviewers are now measured against the same synthetic repo and all three return findings the validator accepts: Codex 4-5, Claude 4 turns, Grok 6 findings via the two-phase path.
