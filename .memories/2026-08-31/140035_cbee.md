## Fixed the flaky ENOTEMPTY test cleanup race from the v0.36.0 tag CI run

**WHAT:** The v0.36.0 tag build failed one test: `supports --ref and --keep-stage against committed fixture history` in `tests/codex-package-script.test.mjs`. The test failed in `cleanupFixture` with `ENOTEMPTY: directory not empty, rmdir .../repo`. The v0.36.1 push and tag runs passed, so main was already green.

**WHY:** The fixture makes git commits in a temp repo. `git commit` can start a detached background maintenance process (`git maintenance run --auto` / `git gc --auto`). That process writes into `.git` while `fs.rmSync` deletes the tree, so the final `rmdir` finds new files and fails. A race, so the test is flaky, not broken.

**HOW:**
- Root cause fix: every temp-repo test fixture now sets `gc.auto=0` and `maintenance.auto=false`, so git never spawns a background writer. Applied to `codex-package-script`, `version-release`, `pre-merge-review-isolation`, `sdd-workspace`, and `borrowed-superpowers` test fixtures (all shared the same latent race).
- Defense in depth: `cleanupFixture` in `codex-package-script.test.mjs` now calls `rmSync` with `maxRetries: 10, retryDelay: 100`, which retries on ENOTEMPTY/EBUSY.

**IMPACT:** Tag builds should no longer fail on this race. The race cannot be reproduced deterministically; verification was a green run of all five edited test files (45 tests pass).
