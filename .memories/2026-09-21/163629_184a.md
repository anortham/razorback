## Fixed redact-outbound false positive on short config words

`skills/security-review/scripts/redact-outbound` failed every security pass on machines with `GCM_CREDENTIAL_STORE=cache` because the name matched `SENSITIVE_ENV_NAME` and the security template contains "cached".

- **Root cause:** `replaceEnvironmentValues` treated any env var with a sensitive-looking name as a secret. A short value was checked as a raw substring of the payload and failed closed.
- **Fix:** values under 8 chars made only of lowercase letters (`/^[a-z]+$/`) are treated as configuration words and skipped. Other short values still fail closed.
- **Error text:** the stderr line now reads `redact-outbound: unable to process input: <reason>`; the env-var case names the variable, never the value.
- **Tests:** `tests/outbound-redaction.test.mjs` gained a `GCM_CREDENTIAL_STORE=cache` case, a test piping the real security template through the redactor, and a `stderrIncludes` check. The old `API_KEY=x` fixture became `p4ss` because a single lowercase letter now counts as a config word.
- **Regression check:** all five adversarial templates (security, codex, claude, grok, agy) pass unchanged with `GCM_CREDENTIAL_STORE=cache`.
- **Impact:** security passes in pre-merge review no longer need `env -u GCM_CREDENTIAL_STORE`.
